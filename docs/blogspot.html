Membuat Aplikasi Pendaftaran Siswa Baru dengan PHP: Admisia

Pada tugas kali ini, saya membuat Admisia, aplikasi pendaftaran siswa baru untuk sekolah fiktif SMK Cakrawala. Aplikasi ini memiliki formulir pendaftaran, daftar pendaftar, halaman detail, edit, dan konfirmasi hapus. Berbeda dengan proyek sebelumnya yang menyimpan data di browser, pada proyek ini PHP memproses isian di server dan menggunakan database.

Materi tugas berasal dari PHP — Hypertext Preprocessor dari Fajar Baskoro. Pada bagian latihan terdapat tautan studi kasus pendaftaran siswa baru. Saya menggunakan alur CRUD pada latihan tersebut sebagai dasar, lalu mengembangkan antarmuka dan validasinya.

1. Memahami Peran PHP di Server

HTML dan CSS menyusun tampilan yang dibaca browser. PHP menerima request, memeriksa input, menjalankan query, lalu mengirimkan HTML sebagai response. Browser menerima hasilnya, bukan source code PHP. JavaScript pada proyek ini hanya membantu navigasi ponsel dan penanda validasi; proses CRUD tetap berjalan tanpa JavaScript. 

Browser mengirim formulir (POST)
              ↓
PHP memeriksa CSRF dan isi formulir
              ↓
PDO menjalankan query ke database
              ↓
PHP mengarahkan ke daftar pendaftar (303)
              ↓
Browser menampilkan data terbaru (GET)

Saya menggunakan Post/Redirect/Get setelah penyimpanan berhasil. Dengan begitu, memuat ulang halaman daftar tidak mengirim formulir pendaftaran yang sama sekali lagi.

2. Menyusun Halaman dan Struktur Proyek

Halaman utama berisi ringkasan, statistik dari database, enam pendaftar terbaru, dan pilihan program keahlian. Halaman Data Pendaftar menyediakan pencarian nama atau sekolah asal, filter jurusan, serta paginasi delapan baris. Formulir dipisahkan dari skrip pemrosesnya agar alur request lebih mudah diikuti.

3. Membuat Database dan Koneksi PDO

Kolom utama tabel calon_siswa meliputi ID, nama, alamat, jenis kelamin, agama, dan sekolah asal. Saya menambahkan jurusan, waktu pendaftaran, serta workspace_id untuk memisahkan data percobaan setiap sesi pengunjung. Tersedia tiga pilihan jurusan: Rekayasa Perangkat Lunak, Teknik Komputer dan Jaringan, serta Desain Komunikasi Visual. 

CREATE TABLE calon_siswa (
    id INT UNSIGNED AUTO_INCREMENT PRIMARY KEY,
    workspace_id CHAR(32) NOT NULL,
    nama VARCHAR(64) NOT NULL,
    alamat VARCHAR(255) NOT NULL,
    jenis_kelamin VARCHAR(16) NOT NULL,
    agama VARCHAR(64) NOT NULL,
    sekolah_asal VARCHAR(64) NOT NULL,
    jurusan VARCHAR(64) NOT NULL,
    created_at DATETIME NOT NULL
);

PDO menyediakan antarmuka koneksi database. Untuk MySQL, konfigurasi dibaca dari environment atau file .env lokal. Contoh dasar berikut menunjukkan pembentukan koneksi tanpa menulis password langsung di source code. 

$dsn = 'mysql:host=127.0.0.1;dbname=pendaftaran_siswa;charset=utf8mb4';
$db = new PDO($dsn, getenv('DB_USERNAME'), getenv('DB_PASSWORD'), [
    PDO::ATTR_ERRMODE => PDO::ERRMODE_EXCEPTION,
    PDO::ATTR_EMULATE_PREPARES => false,
]);

Proyek mendukung MySQL dan SQLite. MySQL digunakan dengan mengimpor database/mysql.sql dan mengatur DB_DRIVER=mysql. Pengaturan bawaan memakai SQLite agar bisa langsung dicoba dengan PHP tanpa menyiapkan server database tambahan. Kedua pilihan tetap memproses query melalui PDO di server.

4. Formulir dan Validasi Input

Formulir mengirim data ke proses-pendaftaran.php dengan metode POST. Setiap input memiliki label dan atribut name agar dapat dibaca melalui $_POST. Validasi HTML membantu pengisian, tetapi PHP tetap memeriksa semua data karena request dapat dikirim tanpa melalui browser.

  • Nama dan sekolah asal harus berisi 2–64 karakter.
  • Alamat harus berisi 5–255 karakter.
  • Jenis kelamin, agama, dan jurusan harus cocok dengan pilihan yang tersedia.
  • Input berbentuk array tidak diterima sebagai teks.
  • Request yang mengubah data harus memiliki token CSRF yang sesuai dengan sesi.

Jika validasi gagal, aplikasi menampilkan penjelasan pada kolom yang perlu diperbaiki dan mempertahankan input sebelumnya. Pesan sukses baru ditampilkan setelah penyimpanan selesai.

5. Menerapkan Create, Read, Update, dan Delete

Create menggunakan INSERT setelah input dinyatakan valid. Read menggunakan SELECT untuk menampilkan daftar dan detail. Update membaca data berdasarkan ID, menampilkan form edit, lalu menjalankan UPDATE. Delete memiliki halaman konfirmasi dan hanya menjalankan DELETE melalui POST. 

// Contoh query update dari aplikasi.
$query = db()->prepare(
    'UPDATE calon_siswa
     SET nama=?, alamat=?, jenis_kelamin=?, agama=?, sekolah_asal=?, jurusan=?
     WHERE id=? AND workspace_id=?'
);
$query->execute([
    $data['nama'], $data['alamat'], $data['jenis_kelamin'],
    $data['agama'], $data['sekolah_asal'], $data['jurusan'],
    $id, $_SESSION['workspace']
]);

Nilai input dikirim terpisah melalui prepared statement, sehingga tidak digabungkan langsung ke string SQL. Semua query data juga membatasi workspace_id. Mengganti ID di URL tidak memberi akses ke ruang demo pengunjung lain.

Saat menampilkan teks ke HTML, aplikasi memakai htmlspecialchars(). Contohnya, teks yang menyerupai tag script akan tampil sebagai tulisan, bukan dijalankan oleh browser. Pencarian juga meng-escape karakter wildcard agar tanda persen diperlakukan sebagai karakter pencarian biasa.

6. Menyesuaikan Tampilan Ponsel

Tampilan menggunakan warna hijau, bidang putih, dan font Inter lokal. Pada layar kecil, sidebar dibuka melalui tombol menu, form berubah menjadi satu kolom, dan tabel dapat digeser secara horizontal. Tombol memiliki area tekan yang cukup besar serta penanda fokus untuk navigasi keyboard. Preferensi reduced motion juga dihormati.

7. Menjalankan dan Menguji Aplikasi

Untuk menjalankan aplikasi, clone repository lalu gunakan built-in server PHP. Folder public harus menjadi document root. Tidak ada proses build frontend dan tidak ada dependensi Composer. 

git clone https://github.com/Boyeep/PWEB-PHP.git
cd PWEB-PHP
php -S localhost:8000 -t public

Jika memakai XAMPP di Windows, perintah PHP dapat diganti menjadi C:\xampp\php\php.exe. Untuk MySQL, jalankan MySQL, impor file SQL, salin .env.example menjadi .env, lalu sesuaikan konfigurasinya. Jangan unggah file berisi kredensial ke GitHub.

Pengujian HTTP mencakup pembuatan data, pembacaan pada request berikutnya, perubahan, penghapusan, pencarian, filter, input tidak valid, CSRF, teks mirip HTML, serta akses ID dari sesi berbeda. Hasil pemeriksaan tersedia di repository pada berkas laporan QA.

8. Deploy ke Vercel

Versi online memakai PHP melalui runtime komunitas vercel-php. File api/index.php membatasi routing ke daftar halaman yang diizinkan. Kode PHP tetap berjalan di server.

Filesystem fungsi serverless bersifat sementara, sehingga file SQLite di dalam proses saja tidak cukup untuk menyimpan data. Pada demo ini, snapshot SQLite dan sesi disimpan pada Vercel Blob privat, lalu dimuat kembali pada request berikutnya. Penulisan memakai ETag agar perubahan dari dua request tidak saling menimpa diam-diam. Snapshot demo diberi masa simpan tujuh hari.

Ini adalah solusi untuk demo kecil dengan maksimal 100 pendaftar per ruang. Untuk penggunaan operasional sekolah, konfigurasi MySQL di server PHP biasa lebih sesuai. Demo ini tidak memiliki sistem akun petugas, tidak menerima data siswa nyata, dan tidak melakukan seleksi penerimaan.

Source code, skema MySQL, panduan, screenshot, dan artikel tersedia di repository PWEB-PHP. Aplikasi dapat dicoba melalui demo Admisia.
